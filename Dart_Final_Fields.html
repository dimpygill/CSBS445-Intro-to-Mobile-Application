Understanding final Fields in Dart

Beginner reference • Classes, objects, and constructors

A final field is an instance variable that can be assigned a value only once. Once initialized, the field cannot be assigned a different value.

1. Regular Field vs. Final Field

class Student {
  String name = "John";       // Regular field: can change
  final int studentId = 101; // Final field: assign once
}

void main() {
  Student s = Student();
  s.name = "Mary";           // Allowed
  print(s.name);             // Mary
  print(s.studentId);        // 101
  // s.studentId = 202;    // ERROR: final field
}
Output: Mary
101

name can be reassigned. studentId cannot be reassigned after its initial value is set.

2. Traditional Constructor with an Initializer List

class Student {
  final int studentId;
  String name;

  // Initialize fields before the constructor body runs
  Student(int id, String studentName)
      : studentId = id,
        name = studentName;
}

void main() {
  Student s = Student(101, "John");
  print(s.studentId); // 101
  print(s.name);      // John
  s.name = "Mary";   // Allowed
  // s.studentId = 202; // ERROR
}
Output: 101
John
Important: An uninitialized final instance field cannot be assigned inside an ordinary generative constructor body. Initialize it with an initializer list or this.field in the constructor parameters.

3. Constructor Shorthand: this.field

class Student {
  final int studentId;
  final String name;

  // Shorthand initializes both final fields
  Student(this.studentId, this.name);

  void display() {
    print("$studentId - $name");
  }
}

void main() {
  Student s = Student(101, "John");
  s.display(); // 101 - John
}
Output: 101 - John

The constructor assigns each argument directly to the corresponding field.

4. Final Fields with Named Parameters

class Product {
  final String name;
  final double price;

  Product({
    required this.name,
    required this.price,
  });
}

void main() {
  Product p = Product(name: "Laptop", price: 899.99);
  print(p.name);  // Laptop
  print(p.price); // 899.99
}
Output: Laptop
899.99

required means the caller must supply that named argument. final means the field cannot be reassigned afterward.

5. Final Does Not Make a List Unchangeable

class ShoppingCart {
  final List<String> items = [];

  void addItem(String item) {
    items.add(item); // Allowed: modify existing list
  }
}

void main() {
  ShoppingCart cart = ShoppingCart();
  cart.addItem("Book");
  cart.addItem("Pen");
  print(cart.items); // [Book, Pen]
  // cart.items = ["Laptop"]; // ERROR: reassignment
}
Output: [Book, Pen]

The items field always refers to the same list, but elements can still be added to that list.

6. Comparison: Regular, Final, and Const

DeclarationCan reassign?When is it initialized?
int age = 20;YesWhen the object is created
final int id = 101;NoOnce, during object initialization
static const int max = 100;NoCompile time
Remember: final means assign once—not necessarily that the object or collection it refers to can never change. Constructors often initialize final fields so each instance has its own fixed field values.
