📦 Step 2

The Task Data Model

Before building any UI, define what a task is. Every task in the app will be an instance of the Task class you write here.

Why a Data Model First?

A data model is a Dart class that describes the shape of your data. Think of it as a blueprint: every task in the app will be built from this blueprint.

Our task needs to store:

  • A name (String) — what the task is
  • A priority (String) — "High", "Medium", or "Low"
  • A isDone flag (bool) — whether the task is complete
  • An id (String) — a unique identifier so we can find and delete specific tasks

Write the Task Class

Open lib/models/task.dart and write this:

lib/models/task.dart
Dart
class Task { final String id; final String name; final String priority; bool isDone; Task({ required this.id, required this.name, required this.priority, this.isDone = false, }); }
final String id
final means this value is set once and never changed. Every task gets a unique ID when created so we can identify it later (especially for deletion).
bool isDone
Notice isDone is NOT final — it needs to change when the user marks the task complete. This is the only mutable property.
required this.name
required means you must pass this value when creating a Task — you can't leave it out. The this. shorthand sets the property directly.
this.isDone = false
A default value: new tasks start as not done. You can override this when creating a Task, but you don't have to.

How You'll Use It

Here's a preview of how we'll create tasks later. You don't need to write this now — just understand what the model enables:

Usage Preview
Dart
// Creating a new task final newTask = Task( id: DateTime.now().millisecondsSinceEpoch.toString(), name: 'Complete homework', priority: 'High', ); // Marking it done newTask.isDone = true; // A list of tasks List<Task> tasks = [newTask];
💡
ID trick: DateTime.now().millisecondsSinceEpoch.toString() gives us a unique number based on the current time in milliseconds. It's not the most sophisticated ID system, but it works perfectly for a beginner project where tasks are added one at a time.

Home Screen — Shell

Build the structural skeleton of the Home Screen: the StatefulWidget, the task list in state, and the AppBar. The task list display comes next.

Why StatefulWidget?

The Home Screen needs to hold the list of tasks and rebuild whenever a task is added, removed, or marked complete. That's exactly what StatefulWidget is for.

The Home Screen Shell

Open lib/screens/home_screen.dart and write this. Read the explanation below before moving on.

lib/screens/home_screen.dart
Dart
import 'package:flutter/material.dart'; import '../models/task.dart'; class HomeScreen extends StatefulWidget { const HomeScreen({super.key}); @override State<HomeScreen> createState() => _HomeScreenState(); } class _HomeScreenState extends State<HomeScreen> { // Our task list — starts with some sample tasks final List<Task> _tasks = [ Task(id: '1', name: 'Complete Math homework', priority: 'High'), Task(id: '2', name: 'Read Chapter 4', priority: 'Medium'), Task(id: '3', name: 'Submit project draft', priority: 'Low'), ]; // Toggle a task between done and not done void _toggleTask(String id) { setState(() { final task = _tasks.firstWhere((t) => t.id == id); task.isDone = !task.isDone; }); } // Delete a task void _deleteTask(String id) { setState(() { _tasks.removeWhere((t) => t.id == id); }); } // Add a new task (called after returning from AddTaskScreen) void _addTask(Task task) { setState(() { _tasks.add(task); }); } @override Widget build(BuildContext context) { return Scaffold( appBar: AppBar( title: const Text('📚 My Tasks'), backgroundColor: Theme.of(context).colorScheme.inversePrimary, ), body: const Center( child: Text('Task list coming in next step!'), ), ); } }
import '../models/task.dart'
.. means "go up one folder" — from screens/ up to lib/, then into models/task.dart.
final List<Task> _tasks
The list itself is final (the variable won't be reassigned), but the contents of the list can still change — we can add and remove items freely.
_tasks.firstWhere((t) => t.id == id)
Searches the list for the first task whose id matches the given id. The (t) => is a short arrow function — think of it as "for each task t, check if t.id equals id".
task.isDone = !task.isDone
Flips the boolean: if it was true, it becomes false; if it was false, it becomes true. The ! means "not".
_tasks.removeWhere((t) => t.id == id)
Removes every task from the list where the condition is true. Since IDs are unique, this removes exactly one task.
Theme.of(context).colorScheme.inversePrimary
Uses a color from the app's theme — automatically matches the indigo seed color we set in main.dart. No hardcoded hex values needed.

Widget _buildTaskCard(Task task) { // Priority colors final priorityColor = { 'High': Colors.red.shade100, 'Medium': Colors.orange.shade100, 'Low': Colors.green.shade100, }[task.priority] ?? Colors.grey.shade100; final priorityTextColor = { 'High': Colors.red.shade800, 'Medium': Colors.orange.shade800, 'Low': Colors.green.shade800, }[task.priority] ?? Colors.grey.shade800; return Card( margin: const EdgeInsets.only(bottom: 8), child: ListTile( leading: Checkbox( value: task.isDone, onChanged: (_) => _toggleTask(task.id), ), title: Text( task.name, style: TextStyle( decoration: task.isDone ? TextDecoration.lineThrough : TextDecoration.none, color: task.isDone ? Colors.grey : null, ), ), trailing: Row( mainAxisSize: MainAxisSize.min, children: [ Container( padding: const EdgeInsets.symmetric( horizontal: 8, vertical: 3), decoration: BoxDecoration( color: priorityColor, borderRadius: BorderRadius.circular(12), ), child: Text( task.priority, style: TextStyle( fontSize: 11, fontWeight: FontWeight.bold, color: priorityTextColor, ), ), ), IconButton( icon: const Icon(Icons.delete_outline, color: Colors.redAccent), onPressed: () => _deleteTask(task.id), ), ], ), ), ); }
{ 'High': Colors.red... }[task.priority] ?? ...
A Map literal used as a lookup table. We get the color for this task's priority. The ?? (null-coalescing operator) provides a fallback if the priority doesn't match any key.
Checkbox(value: task.isDone, onChanged: (_) => _toggleTask(...))
The checkbox displays the current done state. When tapped, it calls _toggleTask. The _ parameter ignores the new value because we flip the state ourselves in _toggleTask.
TextDecoration.lineThrough
Draws a strikethrough line through the text — a common visual signal that a task is complete.
MainAxisSize.min
Tells the Row to be only as wide as its children need — important here because the Row is inside a ListTile's trailing slot, which has limited space.

Add Task Screen

What This Screen Needs

Full Add Task Screen

Open lib/screens/add_task_screen.dart and write this complete file:

lib/screens/add_task_screen.dart
Dart
import 'package:flutter/material.dart'; import '../models/task.dart'; class AddTaskScreen extends StatefulWidget { const AddTaskScreen({super.key}); @override State<AddTaskScreen> createState() => _AddTaskScreenState(); } class _AddTaskScreenState extends State<AddTaskScreen> { // Controller reads whatever the user typed final _nameController = TextEditingController(); // Selected priority — starts at Medium String _selectedPriority = 'Medium'; // Error message if the user tries to save with an empty name String? _errorText; @override void dispose() { _nameController.dispose(); super.dispose(); } void _saveTask() { final name = _nameController.text.trim(); if (name.isEmpty) { setState(() { _errorText = 'Please enter a task name.'; }); return; } final newTask = Task( id: DateTime.now().millisecondsSinceEpoch.toString(), name: name, priority: _selectedPriority, ); // Pop and pass the new task back to HomeScreen if (!mounted()) return; Navigator.of(context).pop(newTask); } @override Widget build(BuildContext context) { return Scaffold( appBar: AppBar( title: const Text('Add Task'), backgroundColor: Theme.of(context).colorScheme.inversePrimary, ), body: Padding( padding: const EdgeInsets.all(20), child: Column( crossAxisAlignment: CrossAxisAlignment.stretch, children: [ // ── Task Name Field ── TextField( controller: _nameController, autofocus: true, decoration: InputDecoration( labelText: 'Task Name', hintText: 'e.g. Read Chapter 5', border: const OutlineInputBorder(), errorText: _errorText, ), onChanged: (_) { if (_errorText != null) { setState(() => _errorText = null); } }, ), const SizedBox(height: 24), // ── Priority Label ── const Text( 'Priority', style: TextStyle( fontSize: 13, fontWeight: FontWeight.w600), ), const SizedBox(height: 8), // ── Priority Buttons ── Row( children: ['High', 'Medium', 'Low'].map((priority) { final isSelected = _selectedPriority == priority; final color = priority == 'High' ? Colors.red : priority == 'Medium' ? Colors.orange : Colors.green; return Expanded( child: Padding( padding: const EdgeInsets.only(right: 8), child: OutlinedButton( style: OutlinedButton.styleFrom( backgroundColor: isSelected ? color.withOpacity(0.1) : null, side: BorderSide( color: isSelected ? color : Colors.grey, width: isSelected ? 2 : 1), foregroundColor: isSelected ? color : Colors.grey, ), onPressed: () { setState(() => _selectedPriority = priority); }, child: Text(priority), ), ), ); }).toList(), ), const SizedBox(height: 32), // ── Save Button ── FilledButton( onPressed: _saveTask, child: const Text('Save Task'), ), const SizedBox(height: 10), // ── Cancel Button ── OutlinedButton( onPressed: () => Navigator.of(context).pop(), child: const Text('Cancel'), ), ], ), ), ); } }
TextEditingController
Attached to the TextField. We read its .text property when the Save button is pressed to get what the user typed.
dispose() { _nameController.dispose() }
When the screen is removed from the app, we must clean up the controller to prevent memory leaks. Always dispose controllers in dispose().
name.trim()
trim() removes any leading or trailing whitespace. So if the user typed " homework " it becomes "homework". Prevents tasks with blank-looking names.
String? _errorText
The ? means this can be null. When null, no error is shown. When set to a string, the TextField displays it as an error message below the field.
Navigator.of(context).pop(newTask)
Pops back to the Home Screen AND passes the new task along as a return value. This is how data flows back from a pushed screen.
['High','Medium','Low'].map((priority) {...})
Loops over the three priority names and creates an OutlinedButton for each. .toList() at the end converts the result to a List, which Row requires.
CrossAxisAlignment.stretch
Makes every child of the Column stretch to fill the full width — so the buttons and text field span the whole screen, not just their content width.
🗺️ Step 6

Wiring Navigation

The two screens exist — now connect them. Add the floating action button to navigate to Add Task, and catch the returned task to add it to the list.

Two Things to Add in home_screen.dart

  1. A FloatingActionButton (+ button) on the Scaffold
  2. An _openAddTaskScreen() method that pushes to AddTaskScreen and awaits the result

The Navigation Method

Add this method inside _HomeScreenState (alongside the other methods you already wrote):

add inside _HomeScreenState
Dart
// Navigate to AddTaskScreen and wait for a result Future<void> _openAddTaskScreen() async { final newTask = await Navigator.of(context).push<Task>( MaterialPageRoute( builder: (context) => const AddTaskScreen(), ), ); // If the user saved a task (didn't tap Cancel), add it if (newTask != null) { _addTask(newTask); } }
async / await
Navigation is asynchronous — we push a screen and wait for the user to come back. async on the method and await on the push lets us wait without freezing the app.
Navigator.push<Task>(...)
The <Task> tells Flutter what type of value to expect back. When pop(newTask) is called on AddTaskScreen, this is what we receive.
if (newTask != null)
If the user tapped Cancel, pop() was called with no argument, so newTask is null. We only add a task if the user actually saved one.

Add the Import and FloatingActionButton

At the top of home_screen.dart, add the import for AddTaskScreen:
