Dart Inheritance: From Parent and Child Classes to Method Overriding

A step-by-step beginner tutorial with independent runnable examples, expected output, mobile app connections, guided exercises, and a self-check quiz.

Learning objectives

This self-contained tutorial introduces inheritance through classes, objects, fields, constructors, and methods. It then explains method overriding and polymorphism through progressively more detailed examples.

  1. Recognize an is-a relationship.
  2. Use extends to inherit accessible fields and methods.
  3. Pass constructor values to a parent using super.
  4. Explain overriding, @override, and super.method().
  5. Use parent-typed variables to understand polymorphism.

How to practice: Every numbered example is a separate, complete program. Copy only one program at a time into DartPad or a Dart file and run it.

1. Understanding a class and an object

A class defines data and behavior; an object is an instance of that class. This first example establishes the basic vocabulary before introducing inheritance.

class Student {
  String name;
  Student(this.name);
  void introduce() {
    print('My name is $name');
  }
}
void main() {
  Student s = Student('Maya');
  s.introduce();
}
Expected output
My name is Maya

Trace it: The constructor stores Maya in name; the method prints the stored value.

What is inheritance?

Inheritance lets one class reuse accessible instance behavior defined by another class. The existing class is the parent / superclass; the new class is the child / subclass. Write class Dog extends Animal.

Animal parent
eat()
↓ extends
Dog child
bark() + inherited eat()

Is-a test: A dog is an animal, so inheritance is sensible. A dog has a collar, so a collar is better represented by a field rather than inheritance.

2. The first inheritance example

The child defines only bark(). It does not need to copy eat().

class Animal {
  void eat() {
    print('Animal is eating');
  }
}
class Dog extends Animal {
  void bark() {
    print('Woof!');
  }
}
void main() {
  Dog dog = Dog();
  dog.eat();  // Inherited from Animal
  dog.bark(); // Defined in Dog
}
Expected output
Animal is eating
Woof!

Trace it: Dart finds eat() in Animal and bark() in Dog. A child has access to inherited public instance methods.

3. Inherited fields and methods

A child can use a field declared by its parent.

class Person {
  String name = 'Maya';
  void introduce() {
    print('Hello, I am $name');
  }
}
class Student extends Person {
  void study() {
    print('$name is studying Dart');
  }
}
void main() {
  Student s = Student();
  s.introduce();
  s.study();
  s.name = 'Alex';
  s.introduce();
}
Expected output
Hello, I am Maya
Maya is studying Dart
Hello, I am Alex

Trace it: Student inherits name and introduce(). Updating name changes what introduce() prints.

4. Two children share one parent

Different child classes can reuse the same parent method.

class Animal {
  void eat() => print('Eating food');
}
class Dog extends Animal {
  void bark() => print('Woof');
}
class Cat extends Animal {
  void meow() => print('Meow');
}
void main() {
  Dog d = Dog();
  Cat c = Cat();
  d.eat();
  d.bark();
  c.eat();
  c.meow();
}
Expected output
Eating food
Woof
Eating food
Meow

Trace it: Both children reuse eat() but have their own special methods.

Constructor inheritance: an important distinction

Fields and instance methods can be inherited, but constructors are not inherited. A child constructor must arrange for the parent constructor to run. If the parent has an accessible unnamed zero-argument constructor, Dart can call it implicitly. If the parent requires arguments, the child must supply them, often using : super(...) or a super parameter.

5. Parent constructor needs arguments

Here Person requires a name, so Student explicitly passes the name to Person.

class Person {
  String name;
  Person(this.name);
  void introduce() => print('I am $name');
}
class Student extends Person {
  int grade;
  Student(String name, this.grade) : super(name);
  void showGrade() => print('Grade: $grade');
}
void main() {
  Student s = Student('Maya', 12);
  s.introduce();
  s.showGrade();
}
Expected output
I am Maya
Grade: 12

Trace it: Student receives Maya and 12; super(name) initializes the Person part, and this.grade initializes the Student field.

6. Modern shorthand: super parameters

Dart also supports forwarding constructor parameters with super.name.

class Person {
  final String name;
  Person(this.name);
}
class Student extends Person {
  final int grade;
  Student(super.name, this.grade);
}
void main() {
  Student s = Student('Alex', 11);
  print('${s.name}: ${s.grade}');
}
Expected output
Alex: 11

Trace it: super.name forwards the argument to Person(name). This is a concise way to forward a constructor argument to the parent.

7. Order of constructor execution

Observe which constructor body executes first.

class Parent {
  Parent() {
    print('Parent constructor');
  }
}
class Child extends Parent {
  Child() {
    print('Child constructor');
  }
}
void main() {
  Child c = Child();
}
Expected output
Parent constructor
Child constructor

Trace it: The parent constructor completes before the child constructor body runs.

What is method overriding?

Inheritance means the child reuses a parent method. Overriding means the child provides its own implementation of an inherited method. Use @override to make that intention clear and allow the analyzer to check it. The overriding method must have a compatible signature.

8. First method override

Dog replaces the inherited sound() behavior.

class Animal {
  void sound() {
    print('Some animal sound');
  }
}
class Dog extends Animal {
  @override
  void sound() {
    print('Woof!');
  }
}
void main() {
  Animal a = Animal();
  Dog d = Dog();
  a.sound();
  d.sound();
}
Expected output
Some animal sound
Woof!

Trace it: Animal uses the original sound(); Dog uses its overridden sound().

9. Override with a returned value

An override can return a value rather than printing.

class Employee {
  String role() => 'Employee';
}
class Manager extends Employee {
  @override
  String role() => 'Manager';
}
void main() {
  print(Employee().role());
  print(Manager().role());
}
Expected output
Employee
Manager

Trace it: Both role() methods return String, but the implementations differ.

10. Override a method with a parameter

Method parameters must also remain compatible.

class Notification {
  void send(String message) {
    print('Notification: $message');
  }
}
class EmailNotification extends Notification {
  @override
  void send(String message) {
    print('Email: $message');
  }
}
void main() {
  EmailNotification().send('Welcome');
}
Expected output
Email: Welcome

Trace it: The same argument is accepted, but the child changes how the message is presented.

11. Use super.method() to keep parent behavior

An override can add to the parent behavior rather than completely replacing it.

class User {
  void login() {
    print('Checking username and password');
  }
}
class Admin extends User {
  @override
  void login() {
    super.login();
    print('Opening admin dashboard');
  }
}
void main() {
  Admin().login();
}
Expected output
Checking username and password
Opening admin dashboard

Trace it: super.login() explicitly runs the parent method, then the child prints its extra step.

12. Getters can be overridden

A getter can also be overridden in a child class. The example demonstrates how the returned value can vary by object type.

class Product {
  double get price => 100;
}
class SaleProduct extends Product {
  @override
  double get price => 80;
}
void main() {
  print(Product().price);
  print(SaleProduct().price);
}
Expected output
100.0
80.0

Trace it: A getter is accessed without parentheses, and the child supplies a different computed value.

Polymorphism: one parent type, different behaviors

A variable typed as the parent can refer to an object of a child class. Calling an overridden method selects the implementation based on the actual object, not just the variable type. This is called runtime polymorphism.

13. Parent variable referring to a child

Notice the declared type and actual object type.

class Animal {
  void sound() => print('Animal sound');
}
class Dog extends Animal {
  @override
  void sound() => print('Woof');
}
void main() {
  Animal pet = Dog();
  pet.sound();
}
Expected output
Woof

Trace it: pet is declared Animal, but it refers to a Dog. Dog.sound() runs.

14. A list of different child objects

One loop can call the same method on multiple types.

class Animal {
  void sound() => print('Animal sound');
}
class Dog extends Animal {
  @override
  void sound() => print('Woof');
}
class Cat extends Animal {
  @override
  void sound() => print('Meow');
}
void main() {
  List<Animal> animals = [Dog(), Cat(), Animal()];
  for (Animal animal in animals) {
    animal.sound();
  }
}
Expected output
Woof
Meow
Animal sound

Trace it: Each element is treated as Animal, but its actual class determines the sound.

15. Mobile app example: different screen messages

This simplified app example shows how different screens can share an interface-like parent behavior. It uses plain Dart, so Flutter is not required.

class AppScreen {
  String title() => 'App';
  void open() => print('Opening ${title()}');
}
class HomeScreen extends AppScreen {
  @override
  String title() => 'Home';
}
class SettingsScreen extends AppScreen {
  @override
  String title() => 'Settings';
}
void main() {
  List<AppScreen> screens = [HomeScreen(), SettingsScreen()];
  for (AppScreen screen in screens) {
    screen.open();
  }
}
Expected output
Opening Home
Opening Settings

Trace it: open() is inherited unchanged, but it calls the overridden title() for each actual screen object.

16. Mobile app example: notification styles

Use polymorphism to avoid separate if statements for every notification type.

class AppAlert {
  void display(String text) => print('Alert: $text');
}
class SuccessAlert extends AppAlert {
  @override
  void display(String text) => print('SUCCESS: $text');
}
class ErrorAlert extends AppAlert {
  @override
  void display(String text) => print('ERROR: $text');
}
void main() {
  List<AppAlert> alerts = [SuccessAlert(), ErrorAlert()];
  for (AppAlert alert in alerts) {
    alert.display('Saved');
  }
}
Expected output
SUCCESS: Saved
ERROR: Saved

Trace it: The loop calls one common method; each child supplies its own behavior.

Common mistakes and design rules

SituationCorrect understanding
class Dog extends AnimalDog is a subclass of Animal.
Calling inherited eat()Reuse; not overriding.
Writing @override void sound()Child supplies compatible behavior for inherited sound().
super.sound()Explicitly invokes the parent implementation.
super(name)Calls the parent constructor; constructors are not inherited.
Animal a = Dog()Legal: a parent-typed variable can hold a child object.
a.bark() when a is typed AnimalNot allowed unless Animal declares bark() or the type is narrowed.
extends multiple classesDart classes directly extend at most one class.
Private names beginning _Library-private, not simply class-private; visibility depends on the library.
final inherited fieldCan be read but cannot be reassigned after initialization.

Design choice: Prefer inheritance for genuine is-a relationships. For has-a relationships, store an object in a field (composition). Flutter also frequently uses composition to build widget trees.

// A + B + D: run together
class Vehicle {
  void move() => print('Vehicle moving');
}
class Bicycle extends Vehicle {
  @override
  void move() => print('Bicycle pedaling');
  void ringBell() => print('Ring ring');
}
void main() {
  Bicycle b = Bicycle();
  b.move();
  b.ringBell();
  List<Vehicle> vehicles = [Bicycle(), Vehicle()];
  for (Vehicle v in vehicles) {
    v.move();
  }
}
// Output:
// Bicycle pedaling
// Ring ring
// Bicycle pedaling
// Vehicle moving

For A before adding the override, the first line would be “Vehicle moving”. B changes that line because Bicycle overrides move(). D demonstrates polymorphism.

// C: run separately
class Person {
  final String name;
  Person(this.name);
}
class Teacher extends Person {
  final String subject;
  Teacher(String name, this.subject) : super(name);
}
void main() {
  Teacher t = Teacher('Maya', 'Dart');
  print('${t.name} teaches ${t.subject}');
}
// Output: Maya teaches Dart

Teacher passes name to the parent constructor and initializes its own subject field.

Summary

Inheritance: extends shares accessible behavior. Overriding: the child customizes an inherited method. super: accesses a parent constructor or implementation. Polymorphism: a parent-typed reference can invoke different child implementations. These ideas support reusable Dart code and prepare you for Flutter class hierarchies.
