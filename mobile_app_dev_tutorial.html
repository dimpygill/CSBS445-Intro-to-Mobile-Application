Chapter 1

Mobile Application Development

What a mobile application is, how it differs from websites and desktop software, and why cross-platform development exists.

What Is a Mobile Application?

A mobile application (or mobile app) is a software program designed to run on a smartphone or tablet. Unlike a website, a mobile app is installed directly on the device. Unlike desktop software, it is built for a small touch screen and must work with limited battery and memory.

You use mobile apps constantly. A banking app, a weather app, a food delivery app, a to-do list — all of these are mobile applications. What makes them different from the web pages you visit in a browser?

  • Installed on the device. An app lives on your phone. It does not need a browser to run.
  • Can work offline. Many apps store data locally and keep working even without internet.
  • Access to hardware. Apps can use the camera, GPS, fingerprint reader, notifications, and other phone hardware that a browser cannot easily reach.
  • Feels native. A good app follows the design conventions of its platform — it feels like it belongs on the phone, not like a website on a small screen.

Types of Mobile Applications

Not all mobile apps are built the same way. Understanding the different approaches helps you make sense of why tools like Flutter exist.

TypeWhat It IsTechnologiesProsConsExamples
Native AndroidBuilt specifically for AndroidKotlin, JavaBest performance, full hardware accessOnly runs on Android; need separate iOS versionGoogle Maps (Android)
Native iOSBuilt specifically for iPhone/iPadSwift, Objective-CBest performance, full Apple hardware accessOnly runs on iOS; need separate Android versionApple Maps
Cross-platformOne codebase runs on both platformsFlutter, React Native, XamarinWrite once, deploy everywhere; cost-efficientSlight performance trade-offs; platform differencesReflectly (Flutter), Facebook (React Native)
Hybrid / PWAWeb app packaged as an app, or website that behaves like an appHTML, CSS, JavaScriptEasiest to build; works everywhereLimited hardware access; feels like a websiteTwitter Lite

Why Cross-Platform Development Matters

Building two completely separate apps — one for Android, one for iOS — doubles the cost, the time, and the team you need. A company might spend months and significant budget building an Android app, only to start over building the exact same thing for iPhone users.

Cross-platform frameworks solve this. You write your application logic once and the framework handles the differences between Android and iOS for you. Flutter, developed by Google, is one of the most popular cross-platform frameworks available today.

📱
The goal of this tutorial: You will learn to build cross-platform mobile applications using Flutter as the framework and Dart as the programming language. One set of code. Two platforms.

Chapter 2

The Big Picture

What happens when a user interacts with a mobile app? How do all the pieces — Flutter, Dart, a database, and version control — fit together?

What Happens When a User Taps a Button?

When someone uses a mobile application, they see a screen, tap things, type text, and see results. From the user's perspective this feels instant and simple. Behind the scenes, a carefully organised chain of events takes place. Understanding this chain is the foundation of mobile development.

Here is the complete flow for a typical interaction — a user adding a task to a task list:

User taps "Save Task" button ↓ Flutter widget detects the tap ↓ Dart event handler function runs ↓ Application validates the input ↓ Dart calls the database service ↓ SQL command is sent to the database ↓ Database stores the data and returns confirmation ↓ Dart receives the result ↓ setState() tells Flutter the data changed ↓ Flutter rebuilds the widget tree ↓ User sees the new task appear on screen

Each step in this flow belongs to a different layer of the application. Keeping these layers separate — rather than mixing everything into one file — is one of the most important ideas in professional software development.

Where Does Git/GitHub Fit?

Something important to understand immediately: Git and GitHub are not part of the running application. They are part of the development process — the way developers save their work, track changes, and share code with others.

When the book is published (the app is released), readers don't know or care how you tracked your writing history.

Chapter 3

Dart Fundamentals

Variables, data types, control flow, and functions — the building blocks of every Dart program.

What Is Dart?

Dart is a programming language created by Google. It is the language you use to write all the logic in a Flutter application — what the app does, how it responds to the user, and how it manages information. If Flutter is the building, Dart is the engineering that makes it work.

Dart is a strongly typed language, which means every value has a specific type — a number, some text, a true/false value. This helps catch mistakes before the app even runs.

Variables — Storing Information

A variable is a named box that stores a piece of information. You give it a name so you can refer to it later.

📄 Dart — Creating Variables
// Dart knows the type from the value — this is called type inference var taskName = "Buy groceries"; ← Dart infers: String var taskCount = 5; ← Dart infers: int // You can also declare the type explicitly String priority = "High"; int age = 20; double price = 9.99; bool isDone = false;
KeywordMeaningExample
varDart infers the type automaticallyvar name = "Alex";
StringText — always in quote marksString city = "London";
intWhole numbersint age = 20;
doubleDecimal numbersdouble gpa = 3.7;
booltrue or false onlybool isActive = true;
finalSet once, never changed againfinal id = 101;
constKnown at compile time — never changesconst pi = 3.14159;
⚠️
final vs const: Both prevent reassignment. final is determined at runtime (e.g. the current time). const must be known at compile time (e.g. the value of pi). When in doubt, use final.

Null Safety — When a Value Might Not Exist

In real applications, some values might not exist yet. A user might not have entered their name. A database query might return nothing. Dart's null safety system forces you to think about this explicitly.

📄 Dart — Nullable Variables
// Non-nullable — MUST have a value, cannot be null String name = "Alex"; ← always has a value // Nullable — CAN be null (notice the ?) String? middleName = null; ← might not have a value // The ?? operator provides a fallback value String display = middleName ?? "No middle name";

Control Flow — Making Decisions

A program that always does the same thing is not very useful. Control flow lets Dart make decisions and repeat actions.

If / Else

📄 Dart — If / Else
int marks = 75; if (marks >= 90) { print("Grade A"); } else if (marks >= 70) { print("Grade B"); } else if (marks >= 50) { print("Grade C"); } else { print("Fail"); } // Output: Grade B

For Loop

When you need to repeat something a known number of times:

📄 Dart — For Loop
for (int i = 1; i <= 3; i++) { print("Task number: " + i.toString()); } // Output: // Task number: 1 // Task number: 2 // Task number: 3 // for-in: loop over a list of items List<String> priorities = ["High", "Medium", "Low"]; for (String p in priorities) { print(p); }

Functions — Reusable Blocks of Code

A function is a named block of code that performs a specific task. You write it once, then call it wherever you need it. This avoids repeating the same code in multiple places.

📄 Dart — Functions
// A simple function that takes a name and returns a greeting String buildGreeting(String name) { return "Hello, " + name + "!"; } // Named parameters — caller must use the name String createTask({ required String name, String priority = "Medium", ← optional with default }) { return name + " (" + priority + ")"; } // Calling them print(buildGreeting("Jordan")); // Output: Hello, Jordan! print(createTask(name: "Buy groceries", priority: "High")); // Output: Buy groceries (High)
PartMeaning
String before the nameThe return type — what type of value the function gives back
voidThe function returns nothing — it just does something
requiredThis parameter must be provided — it cannot be omitted
= "Medium"A default value used when the caller does not provide one
❌
Common mistake: Forgetting return in a function that has a non-void return type. Dart will show an error if your function says it returns a String but you forget to write return.

Object-Oriented Programming & Collections

Classes, objects, and the collection types that form the backbone of real Dart applications.

Classes and Objects

Imagine you are designing a form for a university. Every student has a name, an ID number, and a grade point average. Instead of managing three separate variables for each student, it would be far more organised to bundle all of a student's information together into a single thing.

That is what a class does. A class is a blueprint that defines what properties and behaviours a particular type of thing should have. An object is one specific instance built from that blueprint.

Collections — Lists, Maps, and Sets

Lists

A List is an ordered collection of items — like a shopping list or a queue. Items keep their position and can be accessed by index (starting from 0).

📄 Dart — Lists
List<String> tasks = ["Math", "Reading", "Project"]; print(tasks[0]); // "Math" (index 0 is the first item) print(tasks.length); // 3 tasks.add("Exercise"); // adds to the end tasks.removeAt(1); // removes "Reading" // Common operations var upper = tasks.map((t) => t.toUpperCase()).toList(); // ["MATH", "PROJECT", "EXERCISE"] var highPriority = tasks.where((t) => t.length > 5).toList(); // tasks with more than 5 characters

Maps

A Map stores key-value pairs — like a dictionary. You look up a value by its key rather than by position. Maps are especially important when working with database results, which arrive as Map<String, dynamic>.

📄 Dart — Maps
Map<String, dynamic> taskRow = { 'id': 1, 'taskName': "Math homework", 'priority': "High", 'isDone': 0, }; print(taskRow['taskName']); // "Math homework" print(taskRow['id']); // 1
💡
Why Map<String, dynamic>? When a database returns a row, the values might be different types — a number, text, a boolean. Using dynamic as the value type tells Dart "this value could be anything." You will convert these maps into proper objects in Chapter 9.

Chapter 5

Asynchronous Programming

Why database and network operations take time, and how Dart's async/await system handles that without freezing the app.

The Problem: Some Things Take Time

Imagine you order food at a restaurant. You do not stand frozen at the counter waiting for your food to be cooked. You go to your table, look at the menu, maybe talk to someone — and when the food is ready, the waiter brings it to you. Life continues while you wait.

Mobile applications face the same challenge. Loading data from a database, downloading an image from the internet, or writing a file to disk all take time — sometimes milliseconds, sometimes seconds. If the app just stopped and waited, the screen would freeze. The user would think the app crashed.

Asynchronous programming allows Dart to start a slow operation, continue doing other things, and handle the result when it arrives.

Synchronous vs Asynchronous

SynchronousAsynchronous
Each step waits for the previous one to finishSlow operations run in the background; other code continues
Simple to understandRequires special keywords (async, await)
Fine for fast operations (math, string formatting)Essential for database calls, network requests, file I/O
Freezes the app if used for slow operationsKeeps the app responsive while waiting

Future — A Promise of a Value

In Dart, a Future<T> represents a value that does not exist yet but will exist sometime in the future. Think of it as a ticket — you have the ticket now, and you will get what it promises when it is ready.

Future<String> means: "a String value that will arrive later."
Future<List<Task>> means: "a list of Tasks that will arrive later."
Future<void> means: "something that will finish later but gives nothing back."

async and await

The keywords async and await are how you work with Futures in a readable way.

  • Add async to a function to indicate it does asynchronous work.
  • Write await before any operation that returns a Future — it pauses that function until the result arrives, without freezing the rest of the app.
📄 Dart — async / await
// Simulating a slow database read (takes 1 second) Future<List<String>> getTasksFromDatabase() async { await Future.delayed(Duration(seconds: 1)); ← simulates waiting return ["Math homework", "Read chapter"]; } // Calling the async function Future<void> loadTasks() async { print("Loading..."); List<String> tasks = await getTasksFromDatabase(); print("Done! Found " + tasks.length.toString() + " tasks"); // Output after 1 second: Done! Found 2 tasks }
PartMeaning
Future<List<String>>This function will eventually return a list of strings
asyncThis function contains asynchronous operations
awaitWait here until the Future completes before continuing
Future.delayed()A built-in way to simulate waiting for a moment

Error Handling — try / catch

Database connections can fail. The network might be down. The server might be busy. Your code must handle these situations gracefully rather than crashing.

📄 Dart — try / catch / finally
Future<void> loadTasksSafely() async { try { // Attempt the operation List<String> tasks = await getTasksFromDatabase(); print("Loaded: " + tasks.length.toString()); } catch (error) { // If anything goes wrong, this runs instead of crashing print("Something went wrong: " + error.toString()); } finally { // This always runs, whether it succeeded or failed print("Loading complete."); } }
🌟
Real-world importance: Every database call in a Flutter application should be wrapped in try/catch. A database might be unavailable, credentials might be wrong, the network might fail. Showing the user a helpful error message is always better than a silent crash.

Chapter 6

Flutter & Widgets

What Flutter is, how it builds a UI from widgets, and the most important widgets you will use in every application.

What Is Flutter?

Flutter is an open-source UI framework created by Google. It lets you build applications for Android, iOS, web, and desktop from a single Dart codebase. Flutter does not use the native components of each platform. Instead, it draws every pixel of the interface itself, using a high-performance rendering engine.

This is why a Flutter app looks identical on Android and iOS — Flutter is not asking Android to draw a button. Flutter is drawing the button itself, consistently, on every platform.

Everything Is a Widget

Flutter's most fundamental rule is this: everything you see on screen is a widget. A button is a widget. A line of text is a widget. The padding around a button is a widget. The entire screen is a widget. Even the invisible structure that arranges things is a widget.

Think of widgets like LEGO bricks. Each one is small and self-contained. You snap them together to build something complex. The result is called the widget tree.

The Widget Tree

MaterialApp └── Scaffold ├── AppBar │ └── Text("My Tasks") └── body └── Column ├── Text("Task 1") ├── Text("Task 2") └── FloatingActionButton └── Icon(Icons.add)

Every widget has a parent and may have one or more children. The build() method on each widget returns its child widgets, forming the tree. When Flutter needs to display the screen, it walks down the tree and paints each widget.

StatelessWidget vs StatefulWidget

There are two fundamental types of widget:

TypeWhen to UseExample
StatelessWidgetThe widget always looks the same — it has no internal data that changes. It just receives data from its parent and displays it.A label showing a fixed piece of text; an icon; a static card
StatefulWidgetThe widget can change while the app is running — it holds state (changing data) and can rebuild itself when that data changes.A checkbox that toggles; a counter button; a form field; any screen that loads data
📄 Flutter — StatelessWidget
class PriorityLabel extends StatelessWidget { final String priority; const PriorityLabel({super.key, required this.priority}); @override Widget build(BuildContext context) { return Text( priority, style: TextStyle(fontWeight: FontWeight.bold), ); } }
📄 Flutter — StatefulWidget with setState()

Layout, State & User Interaction

How Flutter positions widgets on screen, what "state" means, and why setState() is needed to update the UI.

How Flutter Layout Works

Flutter uses a constraint-based layout system. A parent widget gives its child a set of constraints — a minimum and maximum width and height. The child chooses its own size within those constraints, and then the parent positions it.

Parent Widget → passes constraints to Child (min/max width and height) Child Widget → chooses its own size within those constraints Parent Widget → positions the child within itself

Common Layout Patterns

WidgetBehaviourWhen to Use
ColumnStack children vertically. Takes as much vertical space as it needs.A form, a list of labels, a vertical menu
RowPlace children side by side horizontally.A row of buttons, an icon next to text
ExpandedTakes all remaining space in its parent Row/Column.Making a text field fill the remaining width
PaddingAdds empty space around its child.Spacing around any widget
SizedBoxCreates a fixed-size empty space.Gaps between widgets: SizedBox(height: 16)
CenterCenters its child within the available space.Centering a message or loading indicator
⚠️
Common layout error — RenderOverflow: This happens when a Column or Row tries to fit more content than it has space for. Fix: wrap the Column in a SingleChildScrollView to make it scrollable, or use Expanded to distribute space properly.

Understanding State

State
Simple meaning: "Information that can change while the app is running."
In Flutter, state is data held inside a StatefulWidget that affects what the screen looks like. When state changes, Flutter rebuilds the relevant part of the widget tree to reflect the new data.

Think of the difference between a static poster and a digital sign. A poster always shows the same thing — it has no state. A digital sign can change what it displays — it has state. A task list that shows items as "done" or "not done" has state. A counter that increases when you tap a button has state.

Why You Cannot Just Change a Variable

This is one of the most important things to understand about Flutter. Imagine you have a task marked as done and you change its isDone property directly:

📄 Flutter — Wrong Way (UI does not update)
// WRONG — the variable changes, but Flutter does not know about it task.isDone = true; // CORRECT — wrap the change in setState() setState(() { task.isDone = true; ← Flutter sees this and rebuilds the widget });

When you call setState(), you are telling Flutter: "The data has changed. Please call build() again and update the screen." Without setState(), Flutter has no way to know that anything changed, so the screen stays the same even though the variable has changed in memory.

initState — Running Code When the Screen Opens

initState() is a lifecycle method that runs exactly once when a StatefulWidget is first inserted into the widget tree. It is the correct place to load data from a database when a screen first opens.

📄 Flutter — initState()
class _TaskListScreenState extends State<TaskListScreen> { List<Task> _tasks = []; bool _loading = true; @override void initState() { super.initState(); _loadTasks(); ← runs once when the screen opens } Future<void> _loadTasks() async { final tasks = await databaseService.getTasks(); setState(() { _tasks = tasks; _loading = false; }); } @override Widget build(BuildContext context) { if (_loading) return Center(child: CircularProgressIndicator()); return ListView.builder( itemCount: _tasks.length, itemBuilder: (context, index) => Text(_tasks[index].name), ); } }

Navigation & Forms

Moving between screens, passing data back and forth, and collecting input from users.

Navigation — Moving Between Screens

Most apps have more than one screen. A task list app might have a list screen and an "add task" screen. Flutter manages this with a navigation stack — a pile of screens, one on top of the other.

  • Navigator.push — puts a new screen on top of the stack (go forward)
  • Navigator.pop — removes the top screen (go back)
Stack before navigation: [ Home Screen ] ← currently visible User taps "Add Task" button → Navigator.push(AddTaskScreen) Stack after push: [ Add Task Screen ] ← currently visible [ Home Screen ] ← underneath User taps Save → Navigator.pop() Stack after pop: [ Home Screen ] ← currently visible again
📄 Flutter — Navigating to Another Screen
// Navigate to the AddTaskScreen and wait for it to close await Navigator.push( context, MaterialPageRoute(builder: (_) => const AddTaskScreen()), ); // After the user returns, reload the task list _loadTasks();
📄 Flutter — Going Back
// Inside AddTaskScreen, after saving — go back to the previous screen Navigator.pop(context);
💡
Why BuildContext? context is Flutter's way of knowing where a widget sits in the widget tree. Navigation needs context to find the Navigator that manages the current stack. Every widget has a context provided by Flutter automatically.

Forms — Collecting Input from Users

A form is a screen or section where the user types text, makes selections, and submits information. In Flutter, forms are typically built with TextField and DropdownButton widgets, controlled by TextEditingController.

TextEditingController

A TextEditingController is attached to a TextField. It lets you read what the user typed at any time, clear the field, or pre-fill it.

📄 Flutter — A Complete Form Example
class _AddTaskScreenState extends State<AddTaskScreen> { final TextEditingController _nameCtrl = TextEditingController(); String _priority = "Medium"; @override void dispose() { _nameCtrl.dispose(); ← always dispose controllers to free memory super.dispose(); } void _save() { // Validation — check the field is not empty if (_nameCtrl.text.trim().isEmpty) { print("Task name is required"); return; } // Proceed to save... } @override Widget build(BuildContext context) { return Scaffold( appBar: AppBar(title: const Text("Add Task")), body: Padding( padding: const EdgeInsets.all(20), child: Column( children: [ TextField( controller: _nameCtrl, decoration: const InputDecoration( labelText: "Task name", border: OutlineInputBorder(), ), ), const SizedBox(height: 16), DropdownButtonFormField<String>( value: _priority, decoration: const InputDecoration( labelText: "Priority", border: OutlineInputBorder(), ), items: ["High", "Medium", "Low"] .map((p) => DropdownMenuItem(value: p, child: Text(p))) .toList(), onChanged: (v) => setState(() => _priority = v!), ), const SizedBox(height: 24), ElevatedButton( onPressed: _save, child: const Text("Save Task"), ), ], ), ), ); } }

How Dart classes bridge the gap between raw database rows and the objects your application actually works with.

What Is a Data Model?

A data model (or simply a model) is a Dart class that represents one record of real-world data. If your database has a Tasks table, you create a Task class in Dart that mirrors its structure.

Without models, your application would pass raw Map<String, dynamic> dictionaries everywhere. That leads to errors, confusion, and code that is difficult to maintain. Models give your data a clear structure, type safety, and meaningful methods.

Building a Model Class

A model class has three parts: the properties (the fields), the constructor (how to create one), and a factory constructor that converts a database row into an object.

📄 Dart — A Complete Model Class
class Task { // ── Properties — mirror the database columns ───── final int id; String taskName; String priority; bool isDone; // ── Constructor ────────────────────────────────── Task({ required this.id, required this.taskName, required this.priority, required this.isDone, }); // ── Factory — converts a database Map to a Task ── factory Task.fromMap(Map<String, dynamic> row) { return Task( id: row['id'], taskName: row['taskName'], priority: row['priority'], isDone: row['isDone'] == 1, ← SQL BIT 0/1 → Dart bool ); } // ── toMap() — converts a Task back to a Map for saving Map<String, dynamic> toMap() { return { 'id': id, 'taskName': taskName, 'priority': priority, 'isDone': isDone ? 1 : 0, ← Dart bool → SQL BIT }; } }
PartMeaning
final int idid cannot be changed after the Task is created — it comes from the database
factory Task.fromMap()A special constructor that reads from a Map and builds a Task object
row['isDone'] == 1SQL Server stores booleans as 0 or 1. This converts to a Dart bool.
toMap()The reverse — converts the Task back into a Map for database operations
🔄
The conversion pattern: Database → fromMap() → Model Object (used in Dart code) → toMap() → Database. This round-trip is the foundation of how applications persist and retrieve data.

Chapter 10

Databases & SQL

What a relational database is, what Microsoft SQL Server is, and the SQL commands used to create, read, update, and delete data.

What Is a Database?

A database is organised storage for information that persists beyond the lifetime of an application. Without a database, all data disappears the moment an application closes.

A relational database organises information into tables — structured like spreadsheets, with rows and columns. Each table represents one type of thing. A row is one record. A column is one property of every record.

Key Database Concepts

ConceptMeaningExample
TableA structured collection of related recordsA Tasks table
RowOne complete recordOne specific task
ColumnOne property of every recordtaskName, priority, isDone
Primary KeyA unique identifier for each row — no two rows can share itid = 1, 2, 3...
NULLA value that does not exist or is unknownA task with no due date yet
ConstraintA rule the database enforces on dataNOT NULL — this column cannot be empty
Default valueA value used when none is providedisDone defaults to 0

Microsoft SQL Server

SQL Server is Microsoft's enterprise relational database management system (RDBMS). It stores, organises, and retrieves structured data. For learning purposes, it runs on your local computer.

An important distinction for beginners:

ThingWhat It Is
SQL ServerThe database engine software that actually stores and manages data
SSMS (SQL Server Management Studio)A graphical tool for connecting to SQL Server, writing queries, and viewing data
SQLThe language you write to communicate with SQL Server — SELECT, INSERT, etc.

SQL — Creating and Managing Data

Creating a Database and Table

📄 SQL — Database and Table Setup
CREATE DATABASE TaskManagerDB; USE TaskManagerDB; CREATE TABLE Tasks ( id INT IDENTITY(1,1) PRIMARY KEY, taskName NVARCHAR(200) NOT NULL, priority NVARCHAR(20) NOT NULL DEFAULT 'Medium', isDone BIT NOT NULL DEFAULT 0 );
SQL PartMeaning
IDENTITY(1,1)Auto-increment: 1, 2, 3... The database assigns this automatically
PRIMARY KEYEach row has a unique id — this is how we find specific records
NVARCHAR(200)Text up to 200 characters; N means Unicode — supports all languages
NOT NULLThis field is required — you cannot insert a row without it
DEFAULT 'Medium'If no priority is provided, the database uses "Medium" automatically
BITStores only 0 (false) or 1 (true) — used for boolean values

CRUD — The Four Database Operations

Every application that stores data performs these four fundamental operations. The acronym CRUD stands for Create, Read, Update, Delete.

📄 SQL — CRUD Operations
-- CREATE: Add a new record INSERT INTO Tasks (taskName, priority) VALUES ('Read Chapter 4', 'High'); -- READ: Retrieve records SELECT * FROM Tasks; SELECT id, taskName FROM Tasks WHERE isDone = 0; -- UPDATE: Modify an existing record UPDATE Tasks SET isDone = 1 WHERE id = 2; -- DELETE: Remove a record DELETE FROM Tasks WHERE id = 2;
⚠️
Always use WHERE with UPDATE and DELETE. Writing DELETE FROM Tasks; without a WHERE clause deletes every row in the table. Always specify which record to affect.

SQL Injection — A Security Warning

Never build SQL commands by directly concatenating user input:

📄 DANGEROUS — SQL Injection Vulnerability
// If the user types: ' OR '1'='1 -- (malicious input) String query = "SELECT * FROM Tasks WHERE taskName = '" + userInput + "'"; // This becomes: SELECT * FROM Tasks WHERE taskName = '' OR '1'='1' -- // The database returns ALL records — a security breach
🔒
Always use parameterised queries — pass values as parameters separate from the SQL text. The database driver ensures user input cannot be interpreted as SQL code. Most database packages handle this for you.
Chapter 11

Connecting an Application to a Database

The service layer, how Dart communicates with SQL Server, and how architecture keeps UI and data logic cleanly separated.

Separating Concerns — The Service Layer

A professional Flutter application does not mix database code with UI code. If a widget is building buttons and calling SQL at the same time, the code becomes difficult to read, test, and maintain.

The solution is to create a dedicated service class — also called a data-access layer — whose only job is to communicate with the database. The UI asks the service for data. The service performs the SQL. The UI never touches SQL directly.

HomeScreen (UI widget) calls: await _taskService.getTasks() ↓ TaskService (service class) opens connection runs: SELECT * FROM Tasks converts rows to Task objects using Task.fromMap() returns: List<Task> ↓ HomeScreen receives the List<Task> calls setState() to update the UI ↓ Flutter rebuilds the screen with the new data

A Database Service in Practice

A service class typically contains one method per database operation. Here is what a task management service would look like conceptually:

📄 Dart — Database Service (concept)
class TaskService { // ── Connection settings ────────────────────────────────────── static const _server = 'localhost'; static const _database = 'TaskManagerDB'; static const _username = 'your_username'; static const _password = 'your_password'; // ── Connect to the database ────────────────────────────────── Future<void> connect() async { // Use a database package to open the connection } // ── Read all tasks ──────────────────────────────────────────── Future<List<Task>> getTasks() async { try { final rows = await /* run: SELECT * FROM Tasks */; return rows.map((row) => Task.fromMap(row)).toList(); } catch (e) { print("Failed to load tasks: " + e.toString()); return []; ← return empty list rather than crash } } // ── Insert a new task ───────────────────────────────────────── Future<void> addTask(String name, String priority) async { await /* run: INSERT INTO Tasks (taskName, priority) VALUES (...) */; } // ── Update a task's isDone status ───────────────────────────── Future<void> setDone(int id, bool isDone) async { int bit = isDone ? 1 : 0; await /* run: UPDATE Tasks SET isDone = $bit WHERE id = $id */; } // ── Delete a task ───────────────────────────────────────────── Future<void> deleteTask(int id) async { await /* run: DELETE FROM Tasks WHERE id = $id */; } }

Packages — Extending Dart with Libraries

Dart by itself cannot talk to SQL Server. You need a package — a library written by someone else that provides that capability. Packages are listed in pubspec.yaml and downloaded with flutter pub get.

For connecting to Microsoft SQL Server, packages such as mssql_connection provide the connection mechanism. The exact API varies by package, but the pattern is always: open connection → run query → receive results → close or reuse connection.

A Critical Architecture Note — Production Considerations

Connecting a mobile application directly to a database is acceptable for learning and small-scale projects, but it is not the recommended approach for production applications. Here is why:

Project Structure — Organising Your Code

As an application grows, putting all code into main.dart becomes unmanageable. Professional Flutter projects use a folder structure that separates concerns clearly.

lib/ main.dart ← App entry point only models/ task.dart ← Task class with fromMap() and toMap() product.dart ← Other model classes... services/ task_service.dart ← All SQL operations for tasks auth_service.dart ← Login/auth operations screens/ home_screen.dart ← Task list UI add_task_screen.dart ← Add task form widgets/ task_card.dart ← Reusable task card widget priority_badge.dart ← Reusable priority label
📐
A useful rule: If you are in a screen file and you are writing SQL, stop — that SQL belongs in a service. If you are in a service file and you are building widgets, stop — that widget code belongs in a screen. Keep each file focused on exactly one responsibility.

Git & GitHub — Version Control

How to track changes to your code, work safely, and collaborate — even on your own.

What Is Version Control?

Imagine writing a long document and saving it as Essay_v1.docx, Essay_v2.docx, Essay_final.docx, Essay_final_FINAL.docx. That is a manual version control system. It works, but it is messy, takes space, and makes it hard to see exactly what changed between versions.

Git solves this properly. It tracks every change to every file in your project, stores them efficiently, lets you go back to any previous state, and lets multiple people work on the same code without conflicts.

Git vs GitHub

GitGitHub
Software installed on your computerA website (github.com)
Tracks changes locally on your machineStores your Git history online
Works completely offlineRequires internet
The core technologyA hosting service for Git repositories
Free, open-sourceFree for public repos; paid plans for more features

Core Git Concepts

Repository (repo)
A folder Git is tracking — everything inside it is version-controlled.
Contains the project files AND a hidden .git folder where Git stores all the history.
Commit
A saved snapshot of your code at a specific moment in time.
Each commit has a unique ID, a message describing what changed, and a reference to its parent commit. Commits are permanent — you can always go back to one.
Staging Area
A waiting room for changes before they become a commit.
git add moves changes to the staging area. git commit takes everything in the staging area and creates a permanent snapshot.

The Everyday Git Workflow

Working Directory Staging Area Repository (GitHub) (your code files) Edit files ↓ git status (see what changed) ↓ git add . → Changes staged (stage all changes) ↓ git commit -m "message" → Snapshot saved locally ↓ git push origin main (uploaded to GitHub)

Essential Git Commands

Testing, Debugging & Security

Verifying that your application works correctly, finding and fixing problems, and protecting data.

Testing — Why It Matters

There is a fundamental difference between these two statements:

  • "I wrote the code and it compiles."
  • "I know the application works correctly."

Code that compiles without errors can still behave incorrectly, crash in specific situations, or lose data. Testing is the process of systematically verifying that the application does what it is supposed to do.

Manual Testing — Test Cases

Manual testing means operating the application yourself and checking that each feature works as expected. The key is to test systematically using written test cases, not just clicking around hoping nothing breaks.

Debugging — Finding What Went Wrong

Debugging is the process of identifying the cause of unexpected behaviour. When something goes wrong, the instinct is to panic. The professional approach is to be methodical.

Reading Error Messages

An error message is not a sign that something is catastrophically broken — it is a clue. Read it carefully before trying to fix anything. Error messages usually tell you:

  • What type of error occurred
  • Which file and line number it happened on
  • What Dart or Flutter expected vs. what it got

Systematic Debugging Approach

Problem observed ↓ Identify WHICH layer the problem is in: UI? → Check build() method and setState() calls Logic? → Check Dart functions and conditions Service? → Check database calls and SQL Database? → Run the SQL directly in SSMS Connection? → Check credentials and server settings ↓ Add print() statements to see values at each step ↓ Isolate the problematic line ↓ Fix and test again

Security Basics — Protecting Your Code and Data

Never Commit Secrets to GitHub

Once a password or API key is pushed to GitHub — even to a private repository — it should be considered compromised. People scan GitHub for accidentally committed credentials continuously. The rule is absolute: no credentials in source code.

.gitignore — Telling Git What to Ignore

A .gitignore file lists files and folders that Git should never track. Common entries for Flutter projects:

📄 .gitignore — Flutter Project
# Flutter build output — never commit these build/ .dart_tool/ .flutter-plugins .flutter-plugins-dependencies # Credentials and environment files *.env secrets.dart config_local.dart # macOS system files .DS_Store # VS Code settings (personal preference, not code) .vscode/

Where Should Credentials Live?

In a learning project, credentials may be in a configuration file. In a production application:

  • Use environment variables set on the server
  • Use a secrets management service
  • Keep credentials only on the backend server, never in the mobile app

This reinforces why the API/backend architecture described in Chapter 11 is the correct approach for production — the mobile app never needs to know the database password.

Common Beginner Misconceptions

❌
Flutter is a programming language.
Flutter is a framework — a collection of tools, libraries, and components for building UIs. The programming language is Dart. You write Dart code that uses the Flutter framework.
✅ Flutter is the framework. Dart is the language. They work together but are distinct.
❌
Git and GitHub are the same thing.
Git is software that runs on your computer and tracks changes. GitHub is a website that hosts Git repositories online. You can use Git without GitHub.
✅ Git = version control tool on your computer. GitHub = online hosting service for Git repositories.
❌
setState() saves data to the database.
setState() tells Flutter to rebuild the UI. It has absolutely nothing to do with databases. To save to a database, you call your service method. To update the UI after saving, you call setState().
✅ setState() updates the screen. Database operations update the database. These are completely separate concerns.
❌
If the code compiles, the application is working correctly.
Compilation only checks that the syntax is valid Dart. It does not check that the logic is correct, that the database connection works, or that the UI behaves as expected. Testing is necessary to confirm the application works.
✅ A compiling app is a starting point, not a finished product. Test every feature explicitly.
❌
Putting everything in main.dart is fine for small apps.
Even small apps benefit from clear structure. main.dart with hundreds of lines of mixed UI, database, and logic code is difficult to debug, maintain, or extend. Good habits established on small projects carry into large ones.
✅ Always separate screens, models, and services into their own files from the start.

A concise reference for every key term introduced in this tutorial.

async
A Dart keyword that marks a function as asynchronous — it contains operations that take time and uses await internally.
await
A Dart keyword that pauses the current function until a Future completes, then continues with the result — without blocking the whole app.
BuildContext
An object Flutter provides to every widget's build() method that describes the widget's position in the widget tree. Required for navigation and some lookups.
CRUD
Create, Read, Update, Delete — the four fundamental database operations. Maps to INSERT, SELECT, UPDATE, DELETE in SQL.
commit
A Git snapshot of code at a specific point in time, with a message describing what changed.
Dart
The programming language developed by Google and used to write all Flutter application logic.
Flutter
An open-source UI framework developed by Google for building cross-platform applications from a single Dart codebase.
Future
A Dart type representing a value that will be available sometime in the future — the result of an asynchronous operation.
Git
An open-source distributed version control system that tracks changes to code files over time.
GitHub
A web-based hosting service for Git repositories, enabling remote storage, collaboration, and code sharing.
hot reload
A Flutter feature that updates the running app with code changes in under a second, preserving the current app state.
initState()
A Flutter lifecycle method in StatefulWidget that runs once when the widget is first inserted into the widget tree. Ideal for loading initial data.
model
A Dart class that represents one record of application data. Contains properties, a constructor, and often fromMap() and toMap() methods for database integration.
Navigator
The Flutter class that manages the navigation stack — pushing new screens and popping them off.
null safety
A Dart language feature that forces you to explicitly declare whether a variable can be null, preventing null reference crashes at compile time.
primary key
A column in a database table whose value uniquely identifies each row. Typically an auto-incrementing integer called id.
repository
A directory tracked by Git, containing all project files plus the complete commit history stored in a .git subfolder.
service
A Dart class whose sole responsibility is performing database or network operations. Keeps UI code clean by isolating data-access logic.
setState()
A method in StatefulWidget that notifies Flutter that state has changed, triggering a rebuild of the widget and its children.
SQL
Structured Query Language — the standard language for creating, querying, and managing relational databases.

Microsoft's enterprise relational database management system (RDBMS) that stores and manages structured data.

state
Information that can change while an application is running and that affects what the screen displays.
