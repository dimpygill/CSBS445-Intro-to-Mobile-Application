📱 Course Overview

This course introduces the concepts, opportunities, and challenges of mobile application development. Students learn to design, develop, test, and deploy mobile applications using the Dart programming language and the Flutter development environment. Every class session combines concept instruction with hands-on lab work — you will write real code every week.

This is the first course in a three-course mobile application development sequence. The emphasis here is on fundamentals and hands-on practice. Advanced topics — networking, databases, advanced state management — are covered in the later courses.

Prerequisites: Grade of "C" or higher in CSE 223. Admission into the BS Computer Science program is required for enrollment.

Note: Students cannot receive credit for both CSE 445 and CSBS 445.

CSE 223 (C or higher) BS CS Program Admission
🗺️ What You'll Learn

This course is built around the full mobile development life cycle — from the first sketch of an app idea all the way to a working, tested build. You will learn how professional mobile apps are designed, developed, tested, and prepared for deployment.

By the end of this course, students will be able to:

Explain & Design

› The mobile app development life cycle

› Mobile UI following Material Design

› Touch targets, screen constraints & accessibility

› Responsive layouts for varying screen sizes

Implement

› Dart: types, null safety, functions, classes, List, Map

› Multi-screen Flutter apps with widgets & layouts

› User input, form validation, setState

› Navigation between screens

Test, Debug & Build

› Dart unit tests and Flutter widget tests

› Run and debug on Chrome and Android

› Debug vs. release builds

› Generate a release APK; understand app-store deployment
🎯 Final Mini-Project — Week 12 Students build and present a complete 2–3 screen Flutter app demonstrating navigation, state management, a Dart model class, and at least one passing automated test. The app must run on a mobile target (Android emulator or physical device).
🛤️ How the Course Unfolds

The course is organized into six units across twelve weeks. Each class is 2 hours — approximately 40 minutes of concept instruction followed by 80 minutes of hands-on work. The units below show how topics build on each other and when graded activities are expected.

📌 This is a tentative plan — everything below is subject to change. The order of topics, number and type of assignments, assessment formats, and all due dates may shift based on how the class progresses. I will communicate any changes clearly through Canvas with reasonable advance notice.
1

Unit 1 — Mobile Concepts & Environment · Weeks 1–2

Week 1 · Mobile App Development Life Cycle  |  Week 2 · Dev Environment + First Flutter App

Week 1 grounds the course in the mobile SDLC — ideation, design, development, testing, deployment, and maintenance — and explores how mobile development differs from web and desktop. Students sketch a paper app blueprint and map it through all six stages. Week 2 is hands-on from the start: students install Flutter, VS Code, and the Flutter extension, create their first project, and run a customized Hello World app in Chrome with hot reload.

🔑 Key concepts:
· Mobile SDLC stages  · How mobile differs from web/desktop
· Flutter ecosystem  · VS Code + Flutter SDK setup
· Project structure: lib/, pubspec.yaml, main.dart  · Hot reload

📝 Graded Activity (Week 1): Paper app blueprint with SDLC mapping — kept for Week 12 reflection.
📝 Graded Activity (Week 2): Running Flutter app on Chrome with customized text, color, and icon.
2

Unit 2 — Dart Foundations · Weeks 3–4

Week 3 · Types, Control Flow & Null Safety  |  Week 4 · Functions, Classes & Collections

Week 3 covers the Dart language essentials every Flutter developer needs: core types (int, String, bool), var/final/const, control flow, and Dart's null safety system — including nullable types (String?), the ?? operator, and when to use ! carefully. Week 4 builds the object-oriented layer: functions with named parameters, classes with required constructor parameters, and the collections (List<T>, Map<K,V>) that every Flutter app uses.

🔑 Key concepts:
· var, final, const  · Core types & type inference  · Null safety: String vs String?
· ?? and ! operators  · if/else, for loops, while loops
· Functions: named parameters, return types  · Classes, constructors with required
· List<T>: add, remove, iterate  · Map<K,V>: key-value lookup

📝 Graded Assignment (due Week 4): DartPad exercises — types/null safety (Week 3) + Student class with List and Map (Week 4).
3

Unit 3 — Flutter UI & Mobile Design · Weeks 5–7

Week 5 · Widgets & Mobile UI Principles  |  Week 6 · Layouts II & Running on Android  |  Week 7 · User Input & Touch-Friendly Forms

Week 5 introduces the widget tree and Flutter's core layout widgets, integrated with mobile design principles: touch targets, Material Design conventions, safe areas, and accessibility labels. Week 6 expands to Scaffold, ListView, and responsive layout — and for the first time students run their app on an Android emulator or physical device, comparing the experience to Chrome. Week 7 covers user input: TextField, TextEditingController, form validation, and designing forms that are comfortable to use on a touchscreen.

🔑 Key concepts:
· Widget tree & StatelessWidget  · Column, Row, Container, Padding, SizedBox, Expanded
· Touch targets (48dp minimum)  · ThemeData & Material Design  · Semantics (accessibility)
· Scaffold, AppBar, ListView, BottomNavigationBar  · Responsive layout with Expanded/Flexible
· Chrome vs Android: touch events, pixel density, safe-area insets
· TextField, TextEditingController, InputDecoration, form validation

📝 Graded Assignment (due Week 7): Scrollable Scaffold app with profile card, ListView, and bottom nav — must run on Chrome and a mobile target (Android emulator or device).
⚙️ Prepare Before Week 6 — Android Development Environment Before Week 6, students should complete the following setup steps using the instructor-provided guide (posted on Canvas):

· Run flutter doctor and review the output
· Verify that Android development tools are installed (Android Studio is used only to support the Android emulator — you do not need to learn Android Studio itself)
· Create an Android Virtual Device (AVD) using AVD Manager, OR prepare a physical Android device with USB or wireless debugging enabled
· Attempt to resolve any major warnings before arriving to Week 6
· Contact the instructor before Week 6 if you encounter a blocking issue

The goal of Week 6 is to spend class time running, comparing, and debugging your Flutter app on a mobile target — not installing software. Students whose Android environment is not working during class may continue in Chrome and troubleshoot the mobile setup separately.
4

Unit 4 — State & Navigation · Weeks 8–9

Week 8 · State Management with setState  |  Week 9 · Navigation

Week 8 introduces the fundamental challenge of reactive UI: why StatelessWidget can't update, how StatefulWidget and setState solve it, and what happens inside a widget rebuild. Students build a to-do list app with add and delete functionality. Week 9 covers Flutter's Navigator stack — push and pop, MaterialPageRoute, named routes, and passing data between screens — extending the to-do app into a two-screen experience.

🔑 Key concepts:
· StatefulWidget two-class pattern  · setState and the rebuild cycle  · Lifting state up
· Navigator as a stack: push, pop  · MaterialPageRoute  · Named routes
· Passing data via widget constructors  · Android back button vs AppBar back arrow

📝 Graded Assignment (due Week 9): To-do list app with add/delete (setState) and a working detail screen (named-route navigation, data passing).
5

Unit 5 — Data Models & Testing · Weeks 10–11

Week 10 · Data Models, Collections & Unit Tests  |  Week 11 · Widget Testing + Mini-Project Workshop

Week 10 introduces the model class pattern — separating data from UI — and the importance of automated testing. Students build a Course catalog app with a typed List<Course>, then write their first Dart unit tests and run them with flutter test. Week 11 introduces Flutter widget tests (WidgetTester, find.text(), tester.tap()), then transitions into an in-class project build session.

🔑 Key concepts:
· Model class pattern  · List<Model> as in-memory data (not persistent storage)
· ListView.builder with typed data  · Why automated testing matters
· test(), expect(), equals()  · Running flutter test in the terminal
· WidgetTester, find.text(), find.byType(), tester.tap()  · Widget test vs unit test

📝 Graded Assignment (due Week 11): Course catalog app + at least 2 passing unit tests + 1 passing widget test — all confirmed via flutter test.
6

Unit 6 — Deployment & Presentations · Week 12

Week 12 · Release Builds, APK Generation & Final Presentations

The final class closes the loop on the mobile SDLC by addressing deployment. Students learn the difference between debug and release builds, what an APK is, and what signing and versioning mean for real-world distribution. The instructor demos flutter build apk --release; students attempt it on their own project. The session ends with final project presentations and a group SDLC reflection connecting back to the paper blueprint from Week 1.

🎯 Final Mini-Project: 2–3 screen Flutter app with Navigator, StatefulWidget + setState, a Dart model class, List/Map collection, and at least one passing automated test. Must run on a mobile target. Students present their app (2–5 minutes depending on class size) demonstrating all required features. Graded project is submitted on Canvas before presentations begin.
