📱 Course Overview

This course introduces the concepts, opportunities, and challenges of mobile application development. Students learn to design, develop, test, and deploy mobile applications using the Dart programming language and the Flutter development environment. Every class session combines concept instruction with hands-on lab work — you will write real code every week.

This is the first course in a three-course mobile application development sequence. The emphasis here is on fundamentals and hands-on practice. Advanced topics — networking, databases, advanced state management — are covered in the later courses.

Prerequisites: Grade of "C" or higher in CSE 223. Admission into the BS Computer Science program is required for enrollment.

Note: Students cannot receive credit for both CSE 445 and CSBS 445.

🛤️ How the Course Unfolds

Each class meets for approximately 2 hours — about 40 minutes of concept instruction followed by about 80 minutes of hands-on work. The roadmap below shows what we cover each week, what you will do in class, and when assignments are expected.

📌 This is a tentative plan — everything below is subject to change. The order of topics, number and type of assignments, assessment formats, and all due dates may shift based on how the class progresses. I will communicate any changes clearly through Canvas with reasonable advance notice.
Week 1 Mobile App Development Life Cycle SDLC

💡 Concepts

· Six SDLC stages: ideation, design, development, testing, deployment, maintenance

· How mobile development differs from web and desktop

· Mobile constraints: screen size, battery, touch input, connectivity, app store gatekeeping

· Where Flutter fits: one Dart codebase, multiple platform targets

💻 Hands-On

· Choose a simple app idea and sketch it on paper (2–3 screens, name, target user)

· Map the idea through all six SDLC stages — what does each look like for your app?

· Brief share-out and class discussion

📝 Assignment: Paper app blueprint with SDLC mapping — submitted as a graded activity and kept for Week 12 reflection.
Week 2 Development Environment + First Flutter App Flutter

💡 Concepts

· Installing Flutter SDK and VS Code with the Flutter/Dart extension

· Chrome as the starting run target — faster setup, same Dart code

· Flutter project structure: lib/, pubspec.yaml, main.dart

· What flutter create and flutter run do; the role of hot reload

💻 Hands-On

· Install Flutter SDK + VS Code extensions (guided walkthrough)

· Run flutter create my_first_app and open in VS Code

· Run on Chrome; modify title, body text, and background color

· Observe hot reload; read main.dart and identify key components

📝 Assignment: Running Flutter app on Chrome with customized text, color, and icon — submitted as a graded activity.
Week 3 Dart Fundamentals I — Types, Control Flow & Null Safety Dart

💡 Concepts

· Variables: var, final, const — when to use each

· Core types: int, double, String, bool and type inference

· Control flow: if/else, for loops, while loops

· Null safety: String vs String?; the ?? operator; when to use ! carefully

💻 Hands-On (DartPad)

· Temperature converter using typed functions

· Grade checker using an if/else ladder

· Nullable name function using ?? for a default value

· Multiplication table using a for loop

📝 DartPad exercises are completed in class. A graded assignment covering Weeks 3–4 material is due at the end of Week 4.
Week 4 Dart Fundamentals II — Functions, Classes & Collections Dart

💡 Concepts

· Functions: named parameters, return types, arrow syntax

· Classes: properties, methods, constructors with named parameters and required

· Creating and using objects: Student(name: 'Ana', major: 'CS', gpa: 3.8)

· List<T>: add, remove, iterate

· Map<K,V>: key-value storage and lookup

💻 Hands-On (DartPad)

· Define a Student class with named-parameter constructor

· Add an isHonorsEligible() method (gpa ≥ 3.5)

· Create a List<Student> and iterate to print each student

· Create a Map<String, String> of course codes to names; look up and print entries

📝 Assignment due this week: DartPad exercises covering Dart types, null safety (Week 3) and functions, classes, List, and Map (Week 4).
Week 5 Flutter Widgets & Mobile UI Principles Flutter · Design

💡 Concepts

· Everything in Flutter is a widget — understanding the widget tree

· StatelessWidget anatomy: build method and BuildContext

· Layout widgets: Column, Row, Container, Padding, SizedBox, Expanded

· Mobile screen constraints: phone dimensions, safe areas, notches

· Touch targets: minimum 48×48 logical pixels for interactive elements

· Material Design basics: typography, spacing, color roles; Semantics for accessibility

💻 Hands-On

· Create a new Flutter project: flutter create profile_card

· Build a profile card: CircleAvatar, name, title, bio using Column and Padding

· Apply a ThemeData color scheme in MaterialApp

· Add a Semantics label to the avatar (accessibility practice)

📝 Profile card is an in-class activity. The graded assignment for this unit is due at the end of Week 7.
⚙️ Prepare Before Week 6 — Android Development Environment Week 6 is your first class running Flutter on a real mobile target. To make the most of that class time, please complete the following steps before Week 6 using the setup guide posted on Canvas:

· Run flutter doctor and review the output
· Verify that Android development tools are installed — Android Studio is used here only to support the Android SDK and emulator; it is not a course topic
· Create an Android Virtual Device (AVD) using AVD Manager, OR prepare a physical Android device with USB or wireless debugging enabled
· Try to resolve any major warnings before Week 6 — contact me on Canvas if you hit a blocking issue

The goal in Week 6 is to spend class time running, comparing, and debugging your Flutter app on a mobile target. Students whose Android environment is not ready during class may continue in Chrome while troubleshooting separately.
Week 6 Layouts, Responsive Design & Running on Android Flutter · Mobile

💡 Concepts

· Scaffold: AppBar, body, BottomNavigationBar — the standard Flutter app shell

· ListView and ListView.builder for scrollable content

· Responsive layout: Expanded and Flexible for varying screen widths

· Chrome vs Android: touch events, pixel density, safe-area insets — how execution differs on a real device

💻 Hands-On

· Add Scaffold with AppBar and BottomNavigationBar to the profile card

· Add a ListView of 6 course tiles (icon, name, credits)

· Verify layout on Chrome, then switch to Android target with flutter run

· Observe and fix any layout differences between Chrome and mobile

📝 In-class lab. Graded assignment covering Weeks 5–7 is due at the end of Week 7.
Week 7 User Input & Touch-Friendly Forms Flutter · Design

💡 Concepts

· TextField and TextEditingController — reading user input

· ElevatedButton, TextButton, OutlinedButton — when to use each

· InputDecoration: labels, hints, error text

· Touch-friendly design: generous tap areas, keyboard types, TextInputAction

· Basic form validation: required fields, format checks, showing errors in the UI

💻 Hands-On

· Build a login screen: email field + password field (obscureText: true) + Login button

· Validate: empty fields, email must contain '@'

· Show error text or a success message based on validation result

· Run on mobile target; confirm touch targets are comfortably sized

📝 Assignment due this week: Scrollable Scaffold app with profile card, ListView, and bottom nav — must run on Chrome and a mobile target (Android emulator or device).
Week 8 State Management with StatefulWidget and setState Flutter

💡 Concepts

· Why StatelessWidget can't update — the problem setState solves

· The StatefulWidget two-class pattern (widget class + state class)

· How setState triggers a widget rebuild

· Lifting state up: when data needs to live above the widget that displays it

💻 Hands-On

· Warm-up (15 min): Build a counter with + and − buttons using setState

· Main activity: Build a to-do list — TextField + Add button appends to a List<String>

· Display with ListView.builder; add a delete button per item

· Show an empty-state message when the list has no items

📝 In-class lab. Graded assignment covering Weeks 8–9 is due at the end of Week 9.
Week 9 Navigation & Passing Data Between Screens Flutter

💡 Concepts

· Navigator as a stack: push adds a screen, pop removes it

· MaterialPageRoute — wrapping a widget as a routable destination

· Named routes: defining a route map in MaterialApp

· Passing data between screens via widget constructors; Android system back vs AppBar back arrow

💻 Hands-On

· Add a detail screen to the Week 8 to-do list app

· Tapping a to-do item navigates to the detail page with the item's text

· Register both screens as named routes in MaterialApp

· Confirm AppBar back arrow and Android system back button both work

📝 Assignment due this week: To-do list app with add/delete (setState) and a working 2-screen navigation with named routes and data passing.
Week 10 Data Models, Collections & Unit Testing Dart · Testing

💡 Concepts

· Model class pattern: a plain Dart class that represents one record

· List<Model> as in-memory data — not persistent storage (persistence is a later-course topic)

· ListView.builder with a typed model list

· Why automated testing matters: catch regressions, document behavior

· Anatomy of a Dart unit test: test(), expect(), equals(); running with flutter test

💻 Hands-On

· Create a Course model class with named-parameter constructor (title, credits, description)

· Define a List<Course> with 6 entries in-memory

· Display with ListView.builder; each card navigates to a detail screen

· In the test/ folder, write 2 unit tests; run with flutter test and review output

📝 In-class activity. Graded assignment covering testing (Weeks 10–11) is due at the end of Week 11.
Week 11 Widget Testing + Final Mini-Project Workshop Testing · Project

💡 Concepts

· What a Flutter widget test does: pumps a widget, finds elements, simulates taps

· Key tools: WidgetTester, find.text(), find.byType(), tester.tap()

· Widget test vs unit test — what each covers

· Final mini-project requirements review and peer feedback norms

💻 Hands-On

· Write 1 widget test for the to-do app: verify title appears, enter text, tap Add, confirm item shows

· Run flutter test and confirm it passes

· In-class project build session — work on the final mini-project

· Peer check: does the app run on a mobile target? Does flutter test pass?

📝 Assignment due this week: Course catalog app with at least 2 passing unit tests + 1 passing widget test — all confirmed via flutter test.
Week 12 Release Build, Deployment Concepts & Final Presentations SDLC · Project

💡 Concepts

· Debug vs. release builds: size, performance, what changes

· What an APK is and how it gets onto an Android device

· Generating a release APK: flutter build apk --release

· Signing and versioning: conceptual overview of why apps need a signature

· App store deployment overview: Google Play and Apple App Store steps (concept only)

💻 Hands-On

· Instructor demo: flutter build apk --release on the course catalog app

· Students attempt flutter build apk --release on their own mini-project

· Final project demos: 2–5 minutes per student depending on class size — show the app running, at least 2 screens, navigation, a live state change, and a passing test

· Group SDLC reflection: which stages did your project touch? Connects back to the Week 1 blueprint.

📝 Final Mini-Project submitted on Canvas before class begins. Requirements: 2–3 screens, Navigator, StatefulWidget + setState, a Dart model class, List/Map, at least one passing automated test, runs on a mobile target.
