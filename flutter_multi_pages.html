push() opens a new page on top. pop() closes the current page and returns to the previous one.

Think of it like a web browser: clicking a link is push (go forward to a new page), and the Back button is pop (return to where you were).

2b. Understanding Scaffold

A Scaffold is the empty frame of a page. Think of a printed form: before anyone writes on it, it already has a header box at the top and a big main box below. You just fill in each box.

appBartop bar: the page title goes here
bodymain area: text, buttons, images

This is how it looks in code:

Scaffold(
  appBar: AppBar(title: Text('Home Page')),  // fill the top box
  body: Center(child: Text('Hello!')),       // fill the main box
)
1
Scaffold means "give me a blank page with a standard layout."
2
appBar: is what goes in the top bar.
3
body: is what goes in the main area.

Same frame, different content

Every page needs the same basic frame, so homePage, detailsPage and aboutPage each return a Scaffold. Only the title and the body change:

3. How the app starts

When you press Run, Flutter follows this chain from left to right until the Home page appears:

main()The starting point of every Dart program. Runs first.
→
runApp(...)Tells Flutter: "draw this widget on the screen."
→
MaterialAppSets up the app, including the Navigator we'll use for push/pop.
→
home: BuilderCreates a fresh context that sits inside MaterialApp.
→
homePage(context)Our first page is drawn. This is the bottom of the stack.
void main() {
  runApp(
    MaterialApp(
      home: Builder(
        builder: (context) => homePage(context),
      ),
    ),
  );
}
Why do we need Builder? Navigator.push(context, ...) searches upward from context to find a Navigator. The Navigator is created by MaterialApp, so our context must be below MaterialApp. Builder gives us exactly that context, so the buttons on Home can find the Navigator.

6. push() in detail — go forward

1
Open another page: call Navigator.push() and provide the page function inside MaterialPageRoute.

Here is the same code with each part labeled:

Navigator.push(1 context,2 MaterialPageRoute(3 builder: (context) => detailsPage(context),45 ), );
1
Navigator.push — "Put a new page on top of the stack."
2
context — the current page's location, so Flutter can find the Navigator.
3
MaterialPageRoute — wraps the page and gives it the standard slide-in animation.
4
builder: (context) => — a small function. The => means "return this." Flutter calls it when it is ready to draw the new page.
5
detailsPage(context) — our page function that returns the Scaffold for the new page.

Where does push() go?

Put it inside a button's onPressed, so it only runs when the user taps:

ElevatedButton(
  child: Text('Open Details'),
  onPressed: () {
    Navigator.push(
      context,
      MaterialPageRoute(
        builder: (context) => detailsPage(context),
      ),
    );
  },
),
Read it out loud: "When pressed, ask the Navigator to push a new Material route that builds the Details page."

7. pop() in detail — go back

2
Go back: call Navigator.pop(context).
Navigator.pop(context);

pop needs only one thing: context. It doesn't need to know which page to go to, because the previous page is already waiting underneath in the stack.

Two ways to go back

① Your own buttonA "Go Back" button whose onPressed calls Navigator.pop(context).
② The automatic ← arrowWhen a page is pushed, AppBar adds a back arrow for you. Tapping it calls pop. The Android system Back button does the same.
Explain to students: push = go forward to a new page; pop = remove the current page and go back.

Rule: Last page in is the first page out — like a stack of plates. You always add and remove from the top.

9. Complete simple Flutter example

How to run it

1
Quickest (no install): open dartpad.dev in a browser and make sure it is set to Flutter. Delete the sample code.
2
Or on your computer: in a terminal run flutter create nav_demo, then open the nav_demo folder in VS Code or Android Studio.
3
Open lib/main.dart, delete everything inside, and paste the code below.
4
Press Run (DartPad) or press F5 / run flutter run with an emulator, phone, or Chrome selected.
5
Test it: Home → Open Details → Open About → Go Back → Go Back. You should end on Home.

Paste this into main.dart. Each page is just a function that returns a Scaffold.

import 'package:flutter/material.dart';

void main() {
  runApp(
    MaterialApp(
      home: Builder(
        builder: (context) => homePage(context),
      ),
    ),
  );
}

// PAGE 1: HOME
Widget homePage(BuildContext context) {
  return Scaffold(
    appBar: AppBar(title: Text('Home Page')),
    body: Center(
      child: ElevatedButton(
        child: Text('Open Details'),
        onPressed: () {
          Navigator.push(
            context,
            MaterialPageRoute(
              builder: (context) => detailsPage(context),
            ),
          );
        },
      ),
    ),
  );
}

// PAGE 2: DETAILS
Widget detailsPage(BuildContext context) {
  return Scaffold(
    appBar: AppBar(title: Text('Details Page')),
    body: Center(
      child: Column(
        mainAxisSize: MainAxisSize.min,
        children: [
          Text('This is the Details Page'),
          ElevatedButton(
            child: Text('Open About'),
            onPressed: () {
              Navigator.push(
                context,
                MaterialPageRoute(
                  builder: (context) => aboutPage(context),
                ),
              );
            },
          ),
          ElevatedButton(
            child: Text('Go Back'),
            onPressed: () {
              Navigator.pop(context);
            },
          ),
        ],
      ),
    ),
  );
}

// PAGE 3: ABOUT
Widget aboutPage(BuildContext context) {
  return Scaffold(
    appBar: AppBar(title: Text('About Page')),
    body: Center(
      child: ElevatedButton(
        child: Text('Go Back'),
        onPressed: () {
          Navigator.pop(context);
        },
      ),
    ),
  );
}

Line-by-line summary

CodeMeaning
import 'package:flutter/material.dart';Loads Flutter's Material widgets (Scaffold, AppBar, buttons…).
Widget homePage(BuildContext context)A function named homePage that takes a context and returns a Widget (the page).
return Scaffold(...)The page itself: top bar + body.
onPressed: () { ... }Code inside the braces runs only when the button is tapped.
Navigator.push(...)Go forward to a new page.
Navigator.pop(context)Go back to the previous page.

9b. Alternate way: one file per page

Section 9 puts everything in main.dart. That's fine for a small app, but as apps grow, it's easier to give each page its own file. The app works exactly the same; the code is just better organized.

The folder structure

📁 lib
📄 main.dart starts the app
📄 home_page.dart Page 1
📄 details_page.dart Page 2
📄 about_page.dart Page 3
1
In VS Code, right-click the lib folder and choose New File.
2
Create home_page.dart, details_page.dart and about_page.dart.
3
Use lowercase with underscores for file names. That's the Dart naming rule.

How the files connect: import

If a file uses a function from another file, it must import that file:

main.dartuses homePage()
→ imports
home_page.dartuses detailsPage()
→ imports
details_page.dartuses aboutPage()
→ imports
about_page.dartimports no page files
Also remember: every file needs import 'package:flutter/material.dart'; at the top, because every file uses Flutter widgets.

10. Common mistakes and how to fix them

MistakeWhat happensFix
✗ builder: detailsPage(context),Error: the builder must be a function, not a page.✓ builder: (context) => detailsPage(context),
✗ Navigator.push(context, detailsPage(context));Error: push needs a Route, not a Widget.✓ Wrap the page in MaterialPageRoute(...).
✗ Putting push directly in the page instead of inside onPressedThe page opens by itself the moment it is drawn, or the app throws an error.✓ Always put push/pop inside onPressed: () { ... }.
✗ home: homePage(context) directly in mainThere's no context available in main().✓ Use Builder(builder: (context) => homePage(context)).
✗ A "Go Back" button on HomeThere's no page below Home, so pop can leave a black screen or close the app.✓ Only use pop on pages that were pushed.
✗ Missing , or )Red error lines; the app won't run.✓ Add trailing commas and let the editor auto-format (right-click → Format Document).

11. Practice and quick check

Practice tasks

1
Easy: Change the text on each page, e.g. add your name to the About page.
2
Medium: Add a button on Home that opens the About page directly (skipping Details).
3
Challenge: Add a fourth page called contactPage and open it from About. Draw the stack before and after.

Quick check (click to see the answer)

Q1. Which command opens a new page?

Navigator.push() — it puts a new page on top of the stack.

Q2. You are on About. The stack is Home → Details → About. You press Back once. Which page do you see?

Details. pop removes About from the top, so Details is now on top.

Q3. Why do we write builder: (context) => ... instead of just the page?

The builder must be a function. Flutter calls it later, when it is ready to draw the new page.

Q4. What does context help Flutter find?

The Navigator, so push and pop know which stack of pages to change.

Q5. Why doesn't the Home page have a ← back arrow?

Home is the bottom of the stack. There's no page underneath to go back to, so AppBar doesn't show one.

12. Bonus: Other button types

Flutter has several kinds of buttons. They all follow the same pattern as ElevatedButton: something to show, plus onPressed for what it does. Here's how each one looks in a default Flutter app:

Elevated
ElevatedButton

Raised and filled, with a light shadow. Use it for general actions.

ElevatedButton(
  child: Text('Elevated'),
  onPressed: () {},
)
Filled
FilledButton

A solid color with no shadow. Use it for the most important action on a page (e.g. "Save").

FilledButton(
  child: Text('Filled'),
  onPressed: () {},
)
Outlined
OutlinedButton

Just a border, no fill. Use it for secondary actions (e.g. "Cancel").

OutlinedButton(
  child: Text('Outlined'),
  onPressed: () {},
)
Text
TextButton

Plain colored text with no border. Use it for small, low-priority actions (e.g. "Skip").

TextButton(
  child: Text('Text'),
  onPressed: () {},
)
♥
IconButton

Only an icon, no text. Use it for toolbar actions (favorite, search, settings). Note that it uses icon:, not child:.

IconButton(
  icon: Icon(Icons.favorite),
  onPressed: () {},
)
+
FloatingActionButton

A button that floats at the bottom-right. Use it for the page's main action (e.g. ➕ Add).

FloatingActionButton(
  child: Icon(Icons.add),
  onPressed: () {},
)

Where the FloatingActionButton goes

It doesn't go in the body. Scaffold has its own slot for it, called floatingActionButton:.

appBar
body
+ floatingActionButton 
Scaffold(
  appBar: AppBar(title: Text('Home Page')),
  body: Center(...),
  floatingActionButton: FloatingActionButton(
    child: Icon(Icons.add),
    onPressed: () {},
  ),
)

Buttons with an icon and text

Add .icon to the button name, then use icon: and label: instead of child:.

➜  Open Details
ElevatedButton.icon(
  icon: Icon(Icons.arrow_forward),
  label: Text('Open Details'),
  onPressed: () { ... },
)
